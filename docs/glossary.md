# Night Shift Glossary

The ubiquitous language of Night Shift. Docs, the UI, and code use these terms. One name for one thing.

A Flow speaks only in Nodes, Edges, Steps, and Gates. A method's own language (for WTF: Epic, Feature, Trace) lives in the prompts and skills of a Flow, never in the engine.

## Actors

| Term | Meaning | Source |
|------|---------|--------|
| Developer | Owns a clone of the repo and the coding-agent CLIs. Draws Flows, starts Runs, and answers Gates. In local mode, the only user. | PLAN §1 |
| Person | A user account (Better Auth's user). The Person who owns this computer's Device is signed in for you: a request from this computer without a session of its own acts as them. | Devices, slice 2 |
| Member | A Person in a Space, with a role: owner, admin, member or viewer. The role says what they may do there: start Runs, answer Gates, add Projects, save Flows. A viewer only reads. Owners and admins invite people, change roles and remove Members on the Members page; only an owner deletes a Space. A removed Member no longer sees the Space. A personal Space has one Member, its Person: their own Devices need no Offer there. | Devices, slice 2, slice 6; ADR 1 |
| Host admin | The first Person on a Host: on this computer, the Person who owns it. The admin plugin's `admin` role, not a role in a Space. | Devices, slice 6 |
| Invitation | An offer to join one Space with a role, for one email. It is also the account: a Host takes new people by invitation only, so the person makes their account from the invitation's link (`/invite/<id>`), then joins. Night Shift sends no email: the Members page shows the link to copy. It works for seven days, until it is accepted or canceled. A personal Space takes none. | Devices, slice 6 |

## Objects

| Term | Meaning | Source |
|------|---------|--------|
| Space | What is shared, and with whom: Projects, their Runs and Gates, and the Members. A Better Auth organization. Every Person has a personal Space ("Personal") that nobody can be invited to, and everything starts there. A Person has one personal Space per Home Host: when a Device joins its Home Host, the Device's own personal Space and the Person's personal Space there become one, which the Host keeps. In it, every Device of the Person, with its Agent Profiles, CLI Tools and Connections, is usable without an Offer. A Device without a Home Host keeps its own. Every row of a Project, Clone, Run, Step, Session or Event carries its Space; a person always works in one Space at a time (the session's active Space): its lists, starts and project pages. A Run and its Gates open by the run's id from any of the Person's Spaces, with their role in the run's own Space. | Devices, slice 2; ADR 1 |
| Project | A repository, by its remote: the normalised `origin` (`github.com/acme/app`), so its ssh and https URLs are one Project. Its folders are its Clones. A repository without a remote is a Project on one Device only. | Devices |
| Clone | A Project's repository on one Device, at a path. A Device has at most one Clone of a Project. Adding a folder whose `origin` names a known Project makes a Clone of it, not a second Project. | Devices |
| Device | A computer that runs Night Shift, with its own database. One row of the `device` table is this computer: made on the first start, with a random id that never changes and the host name as its name. | Devices |
| Walker | The Device that walks a Run and writes its Events, the only writer of them. A Run another Device walks is read-only here: answering its Gate, sending its Signal, stopping and moving it travel to its Walker as Commands. "Move to…" gives the Run another Walker (`WalkerMoved`), which resumes from the archived Walk state and then logs `WalkerArrived`; until then the Run still arrives, and the new Walker tries again. A Step that waits through the move goes on in its archived Transcript. In a Space that a Host keeps, a Run started from a Device has the Host as its Walker. A Device that cannot reach its Host walks the Runs it starts itself, and the Exchange sends them to the Host when the Link is back. | Devices; ADR 1 |
| Placement | Which Device a Step runs on: the profile's Device when the node names a profile (a profile is its Device and its id, and a node names a profile or a `device`, never both), else the node's `device`, else the Run's Device, else the Walker. The Run's Device is one of the starter's own Devices, or another Person's Device through its Offers into the Space (see Run's Device). It is decided once, when the Run starts, as the Run plan. The Walker stays the Device that walks the Run and makes each Step's calls there through the Host (the work relay, `devices.work`, `devices.call`); the placed Device checks every call itself. A Step whose Device is offline waits until it is online, up to the Run's Stop Time (without one, until a person stops the Run). The Run's Device may be offline at the start too: the Run starts, and its Worktree is made when that Device is back. When the wait starts, the Person the Run runs for gets "<flow> waits for <device>". Night Shift never runs the Step on another Device instead. | Devices, slice 5; ADR 1, ADR 3 |
| Run's Device | The Device where a Run's Steps run when their node names no profile and no Device. The person chooses it when the Run starts ("Device" in Start run). By default it is the Device that started the Run. For a Run started from a Phone or a browser on the Host, it is the Host. When the Host has no Clone of the Project, it is the Device of the Project's latest Run (`lastRunDevice`): Start run and New run mark it, and the person can choose another of their Devices with a Clone. A Host that another Person runs is the default only when its Host admin offers the starter a profile in the Space. Else one of the starter's own Devices with a Clone is. A schedule or a webhook that names no Device takes the same default, for the schedule's Person. One rule decides it for every start (Start place), and Start run marks it. | Devices, slice 5; ADR 1 |
| Start place | Who walks a Run and its Run's Device, decided for every start (a person's, a schedule's, a webhook's) before the Run plan: in a Space a Host keeps, the Host walks while this computer reaches it, and the Run's Device is the one the start names, else the Device that started it. Else this computer walks, on the Device the start names or the default Run's Device. One module (`start-place.ts`) decides it, and the Devices a person chooses from in Start run carry the same default. | Devices; ADR 1 |
| Run plan | Where a Run's Steps run, decided once when it starts: the Run's Device, the Device of each node that names one (with their names), and the Person the Run runs for, as the Host of its Space knows them. The devices' planner makes it (`PlacementPort.plan`), the Run's row keeps it, and the walk only reads it. A move keeps it: only the Walker changes. A Run from before the plan kept names walks on with the names its nodes give. | Devices |
| Hand-off | The Run's work moving to another Device before a Step there: the Device that has it pushes the Run's branch (a worktree with uncommitted changes fails the Step), the next one fetches it into its own worktree of the Run, and the Walker logs `HandedOff`. | Devices, slice 5 |
| Offer | One of a Device's Agent Profiles made available to one Space by the Device's owner (an owner or admin there), with two limits: the widest permission mode its sessions run in, and how many of its sessions run at once (more wait). The only way a Member runs anything on a Device another Person owns: a run there names the offered profile, and the Device runs that profile as its owner set it, with their login and their tools. The Space sees the Device's name and the profile's name and limits, never its settings. Made on the Agents page ("Offer to a Space…"), withdrawn there or on the Devices page; a withdrawn Offer stops the steps that run it. On a Host, its owner (the Host admin) also offers to the personal Space of each Person whose Home Host it is, listed as "Personal of <person>": there the Host is not one of that Person's own Devices. A personal Space that another Host keeps is not listed. A run there that needs the Host without an Offer is refused, and the refusal names the Host admin to ask. Night Shift never makes an Offer on its own. | Devices, slice 6; ADR 1 |
| Offer admission | How the offering Device decides to serve one call of a Run: the starter's role, an Offer in force, its Clone, the Run's own folder, a free session of the Offer and the permission cap. One module (`OfferAdmission`) does it for both paths: in process when the Device walks the Run itself, and after the wire when a Walker elsewhere sends the call through a Host. A call with no starter is refused. Each Offer has one count of its running sessions. | Devices |
| Owner | The one Device that writes a row. Sync never merges two writers of one row: a Run's rows and Events are its Walker's, a Clone is its Device's. | Devices |
| Replica | A Device's own database: everything it may see, as far as it has synced. A Host's Replica keeps every Run its Devices send it. | Devices |
| Device document | A Device's configuration as one Yjs document, `device:<id>`: its Agent Profiles, CLI Tools, Connections, Settings, and its facts (its name, harnesses, programs, secret names with when each was last set and used, Clones). Its Device is its Owner: it applies edits and saves the document in its Replica. Syncs at `/sync`, to its owner only: their sessions, and their other Devices on the Device's Home Host, which each keep a read-only copy. Never holds a secret value. | Devices, slice 3; ADR 1 |
| Host | A Device with "Be a Host" on: other Devices pair with it and connect to it. It has addresses (`https://` names, in the order to try them). It listens on this computer only (`127.0.0.1`) until one of them is `https://`. It records each paired Device and keeps it online while its Link answers. Not an authority over a Device's data. | Devices, slice 4 |
| Home Host | The one Host that keeps a Device's Device document. A Device has at most one. Its other Devices of the same owner open the document there. When a Device joins its Home Host, the Device's personal Space merges into the Person's personal Space there: its Projects, Clones, Runs, Events, Gates, Kept variables, Flows and Schedules move, and a remote that both sides have becomes one Project with a Clone per Device. The merge copies the database first and shows what it moves before it moves it. A remote that a shared Space on the Host has stays apart from it, unless the person chooses to join it. Schedules that name no Device keep firing on the Device that fired them. A Device that joined before the merge existed merges only when its person confirms it: on the Devices page, or with `nightshift merge`. When the Device leaves (Remove access, or `nightshift leave`), it splits off a personal Space of its own with the Projects it has a Clone of, their Flows with their history, Schedules and Kept variables, and the Runs it walked. The Host keeps everything too, and its Space stays on the Device, out of the Space switcher. A Schedule of those Projects that names another Device is paused on the leaving Device, because the Host still fires it there. Turned on, it fires on the leaving Device. A copy of the database comes first. Any Host can be a Home Host: when the Person is not the Host admin, the join screen says that the Host admin can read their personal runs and transcripts. | Devices, slice 4; ADR 1 |
| Guest Host | Any other Host a Device paired with: it gets the shared Spaces of the Device's owner there, never the Device document. A personal Space never merges on a Guest Host. | Devices, slice 4; ADR 1 |
| Home membership | A Device's tie to its Home Host, as one state machine: apart, merging, joined, splitting, and apart again. A join of the Home Host starts the merge. A leave, or a Host that removes the Device's access, starts the split. One step runs at a time on a Device: a second merge is refused ("Wait until it is done."), and a leave waits for the step before it. Each step keeps its state in the Device's database, so a step that a restart cut short goes on from there: a split, and a merge that moved its rows, by themselves, and an earlier merge when the person asks again. The module `HomeMembership` (`devices/src/membership`). | Devices; ADR 1 |
| Pairing | Joining a Device to a Host: Settings → This computer → Join a Host (or `nightshift join <host>`) shows a code, a Person signed in on the Host enters it under Devices → Pair a device and allows it (or runs `nightshift pair <code>` on a Host without a screen), and the Device gets its Device key. Device authorization (RFC 8628). | Devices, slice 4 |
| Way out | How a Host's `https://` address reaches it: its LAN name with its own certificate, a tailnet (Tailscale Serve, Funnel), a public server behind a proxy, or an outbound tunnel. A deployment choice; Night Shift ships none (`docs/deploy/`). | Devices, slice 7 |
| `nightshift` | Night Shift in one file, for a computer without a screen: the daemon, its web UI and its migrations. `nightshift serve`, `join`, `pair`, `admin` (the Host admin's email and password, set on the Host), `leave` (this computer leaves its home Host and keeps its own Personal, ADR 1), and `mcp`: an MCP server on stdio for an agent in a terminal, to list, check and save Flows and start and read Runs through the Night Shift that runs on this computer. An agent reads and saves Flows only through `mcp` and the `nightshift` CLI, and Night Shift checks every save (CLI commands for Flows planned, ADR 2). | Devices, slice 7; Assistant §5; ADR 2 |
| Two-factor sign-in | A code from an authenticator app (TOTP) after the password, or a backup code that works once. A Person turns it on under Account. A Host started with `--require-two-factor` (`NIGHTSHIFT_REQUIRE_TWO_FACTOR=on`) lets a session from another computer do nothing but set it up until it is on (`@nightshift/auth/host-access`). The Host itself and Device keys never need it. A browser can be trusted for 30 days. | Two-factor |
| Device key | What a paired Device signs in with on a Host: an API key of the Person who allowed the pairing, with the Device's id. Hashed on the Host; on the Device, in the keychain or a file only its user can read. Narrower than its Person: `sync`, `relay`, `archive`. Expires after days without use; "Remove access" deletes it. The UI says "access", not "key". | Devices, slice 4 |
| Link | A Device's outbound connection to one Host (a port; `httpsLink` is its adapter): oRPC with the Device key and the relay's WebSocket to the same address. It tries the Host's addresses in order, keeps the first that answers, and sends a heartbeat. It runs the Device's long calls (the Exchange, the work of placed steps) while it is online, and starts them again after a drop or a failure. The Host never calls into a Device. | Devices, slice 4 |
| Peer protocol | The procedures a Device calls on its Host over its Link: `link`, `pairing`, `sync`, `archive`, and the work relay (`devices.work`, `devices.call`). One oRPC contract in `@nightshift/devices` (`hostContract`) names each one, its input and output, and the Device key permission it needs. The Host serves it at `/rpc` (`hostRouter`, mounted by the API); a test runs the same router in memory (`inMemoryHost`). A wire format between daemons of different versions: a change keeps what an older Device sends valid. Not the API a Person's screens call. | Devices |
| Phone | A phone with the Night Shift app, signed in to a Host as a Person. It reads and acts: the Needs-you inbox, Runs, Start run. It runs nothing, so it is not a Device: no Replica, no Link, no Device key. It sees the Spaces that its Host keeps. Those include the Person's one personal Space once their Devices joined that Host, so the Phone sees all personal work. Settings lists each Phone with its name and when it was last seen. "Remove" ends its session and its Push target. | Mobile; ADR 1 |
| Host code | The QR code under Settings, "Use Night Shift on your phone". It holds the Host's https:// address and nothing else: no sign-in, no key. The Night Shift app on a Phone scans it ("Scan the code") to fill in the address; the person then signs in. | Mobile |
| Push target | A browser or a Phone that gets notifications while no Night Shift page is open. Night Shift sends it the ids and one sentence ("A Gate waits for you"), never the question or a transcript. The UI says "this browser" or the Phone's name, and lists them all under "Phones and browsers that can notify you", never "push targets". A browser turns them on in Settings ("Notifications in this browser"). Removing a browser stops its notifications. Removing a Phone also signs it out. | Mobile |
| Notification settings | What a Person gets told about (a Gate waits, a Run finished, a Run failed), on which screens (each browser, each Phone, the desktop app), their Quiet hours, and how long a Phone waits while another screen is open. They belong to the Person, not to a computer: the Settings page shows the same ones on every screen. The phone delay is the wait of a Phone or a closed browser. An answer on one screen clears the notification on every screen. | Mobile |
| Widget | The Night Shift widget on a Phone's home screen (and lock screen on iOS): how many Gates wait for you and the three newest Runs with their status. It shows counts, flow names and statuses only, never what a Gate asks. A tap opens the Needs-you inbox (iOS). | Mobile |
| Follow on the lock screen | Showing one Run's progress outside the app while it runs: its flow, the step that runs now, "Step 2 of 5" and its status. A Live Activity on iOS, an ongoing notification on Android. The person starts it on the run screen or with the switch on the Start tab; it ends when the Run ends. | Mobile |
| Desktop notification | A notification on this computer's own desktop, from Night Shift on this computer, for the Person who owns it. It covers every Space this computer has, also one a Host keeps: it is not a push. It waits while you look at the inbox or the run in the desktop app, or have a Night Shift page open here. | Mobile |
| Keep this computer awake | A setting of this computer (Settings → Runs), off by default. While a run on this computer runs, or sleeps until a timer, the computer does not go to sleep. A run that waits at a Gate does not keep it awake. | Mobile |
| Quiet hours | A daily time window in which Night Shift sends no push. Gates still wait and open pages still update. When Quiet hours end, one notification says how many Gates wait. | Mobile |
| Notifier | The part of Night Shift that reads the runs and tells each Member of a Space about a new Gate, a finished Run and a failed Run, on every screen they use. One daemon sends for each Space: its Host, or for a Device's own personal Space that Device. It also tells the open screens, without a notification, when a Run starts, sleeps, wakes, moves, stops or ends (`run-changed`). | Mobile |
| Live cache | What a screen knows of its Host, kept up to date: one for the web app and the Phone alike (`@nightshift/client`). It follows the Host's notification stream, reads again what each item changes, shows a notice for a new Gate or a Run's end, takes away the notifications of Gates that no longer wait, takes an answered Gate out of the inbox at once, and reads a Run again after a person acts on it. Each app adds only how it shows a notification. The UI never says it. | Mobile |
| Notification key | The id of one notification on every screen: a Gate's Run and Step, a Run's end (a Run can end again after a resume), or the end of quiet hours. A second notification of a key replaces the first, and an answer to a Gate takes its notification back everywhere. The UI never shows it. | Mobile |
| Sync cursor | How far a Replica has exchanged Run history with one Host: per Space and Walker, the last Event it has. The exchange sends what comes after it, in the order it landed on the Host, so each Walker's in its own order. | Devices, slice 4 |
| Exchange | Run history between a Replica and one Host, both ways, by Sync cursor, while the Link is online. The Device pushes the Runs it walks, pulls the others, and takes its Commands on their own stream. The Host serves and keeps them. A batch lands whole, and what follows from it is read from the log. | Devices |
| Landed feed | Every Event of a Run as it lands in this Replica, appended here or brought by the Exchange, with its Space and Walker; and per Space and Walker, the latest `walker_seq` that landed. Read once from the log at the start, then kept from each landing. Its readers (the Exchange, the Notifier, Keep this computer awake) take the Spaces and Walkers they want, with no query. It says whether a Replica at some Sync cursors lacks an Event here before any query. Its readers outside the engine read Landed facts, not the Events. | Performance |
| Landed fact | What one Event of a Run that landed means to a reader of the Landed feed, derived once by the engine from the parsed log: a Gate opened, a wait started (why, and the Device it waits for) or ended, a Step ended, the Run ended (its status), or something else of the Run; and what of the Run it changes: what a list of Runs shows, only the Run's page, or only its spend so far. An Event of an older Walker is upgraded before it lands, so its fact is the same. The Notifier, Keep this computer awake and the Exchange's wait for new rows read them, never an Event's payload. | Architecture 2026-10-29 |
| Command | A person's action on a Run another Device walks: answer its Gate, send its Signal, stop it, move it. The Host checks the Person's role and keeps the Command until the Walker has applied it; the Walker checks again and applies it as its own action, once: the first Event it writes carries the Command's id. Until then it shows as sent. | Devices, slice 4 |
| Archive | The Host's copy of the Walk state of Runs walked elsewhere, per Space: each ended Step's Transcript and command log, and the Run's latest Checkpoints. A Replica opens a Transcript of a Run walked elsewhere from it and keeps a copy. Everything is kept. A running Step's Transcript is followed live instead, while someone watches it: its Walker sends it through the Host on demand. | Devices, slice 4, live transcripts |
| Copy stamp | Which end of its Step a copy of a Step's Transcript or command log holds: the Step's opening (1 for its start, one more for each reopen) and whether that opening had ended. The Walker stamps each copy from its Run Log, so the stamp stays the same when the Run moves. A Replica keeps or serves a copy only when its stamp matches the Step as its own Run Log says. A copy of an earlier end is not there yet: the Replica reads the Step live and later again. A copy without a stamp comes from an older version and counts as a match. | Devices, reopened steps |
| Walk state | What a new Walker resumes a Run from, and what readers of a Run walked elsewhere open: the Run's latest Checkpoint and each Step's Transcript and command log, as files. The engine writes and reads them (`graph/walk-state.ts`); the Archive keeps and carries them. Only the Walker gives them out. | Devices, slice 4 |
| Space document | A Space's definitions as one Yjs document, `space:<id>`: its Projects (name, remote, removed), which Devices have a Clone of each (never the path), and a mirror of its Members. Members read it at `/sync`; they change it only through Night Shift's actions (add, rename, remove, move a Project), which check their role and log an event. The Replica's project rows follow it. | Devices, slice 3 |
| Space move | Projects that go from one Space to another, with their Clones, Runs, Events, Gates, Commands, notifications, Kept variables and Schedules, as one operation of the engine (`Engine.moveProjects`). A person's "Move to…" of a Project, the merge on join and the split on leave (ADR 1) are each one. While it runs, no Run becomes active in the Space it leaves: a person's start, resume, restart or run again is refused ("Try again in a minute."), and a Schedule or the automatic resume after a restart waits for it. Every row moves in one batch, or none does. | Devices; ADR 1 |
| Flow | A directed graph of Nodes and Edges. Night Shift data, not a file in the repository: a Yjs document in the Space that keeps its Project. The Space's Host keeps it (a Space without a Host: its one Device), and every Device of the Space has a copy in its Replica. Edits on a Device that cannot reach the Host merge when the Link is back. A Flow belongs to one Project: "Copy into project" and JSON export and import move it to another. A copy leaves the flows it calls behind, and refuses a name the other Project has. An import of a name the Project has gets a suffix (`-2`). People edit it in the editor, agents through `nightshift mcp` and the `nightshift` CLI. Every save is a Flow revision. | PLAN §2; ADR 2 |
| Flow revision | One save of a Flow: who saved it, when, on which Device, and the change. A person sees the difference between two revisions and restores one: a restore saves the old flow as a new revision, so no revision is lost. A save that changes nothing makes no revision. A Run records the Flow revision it runs. Not a "version": the `version` field of a Flow's JSON is its format version. When a newer Night Shift brings a Flow to its format, that is a revision too ("Updated by Night Shift"): at format 7, each node that named a profile by its name names that Device's profile, by the Device that saved the Flow. A node whose profile Night Shift cannot find keeps the name, and the editor asks to pick the profile again. | ADR 2, ADR 3 |
| Flow document | A Project's flows and schedules as Yjs documents: `flows:<project id>` holds them, `flows-history:<project id>` holds each Flow revision. Every Device of the Space keeps a copy and syncs it with the Host at `/sync`. A Device of a Member whose role may save flows changes its copy, and the edits merge. A browser only reads it and saves through Night Shift's actions. The engine reads and changes it only through `ProjectFlows`, which keeps the Yjs encoding inside. Not the JSON shape of one Flow: that is the flow format (`@nightshift/flows`, `flow/`), with its `version`. | ADR 2 |
| Import on upgrade | The first start after the upgrade to ADR 2: Night Shift reads each Clone's `.nightshift/` Flows, Schedules and profiles once, and never reads the folder again. It deletes a folder that git does not track, and shows a notice for one that git tracks: remove it in a commit. A folder that holds anything it could not import stays too, with a notice. Each profile of the Project becomes a profile of the importing Device, and the nodes that named it reference that profile. When the Device has a profile of that name already, the nodes keep it, and the project's profile comes in as `<name>_project`. When two Clones hold a different Flow of the same name, both come in: the second gets a suffix, its Subflow nodes and Schedules follow the new name, and a notice names both. The same Flow from two Clones comes in once. A folder added as a project later comes in when it is added. The notices show on the project's Flows page until a person dismisses one. | ADR 2, ADR 3 |
| Section | A named, coloured group of Nodes of one Flow, in the editor only: the engine does not see it. Its Nodes form one connected part with one entry. The canvas shows it as one box that keeps its Edges to the rest of the Flow. You open it to see only its Nodes: zoom far into the box, and zoom out to leave. A Section can hold other Sections, which show as boxes inside it. A Node is in the lowest Section that holds it. Not a Subflow: a Section stays in its Flow. | Flow canvas research |
| Node | One step of a Flow: Agent, Command, Tool, Decision, Value, Wait, Subflow (`call` in its JSON), Join, or End. Its id is also its name in templates. | PLAN §3 |
| Agent Node | A Node that runs one Session on its Harness, with a prompt or a skill (with arguments), a model, an effort, and a permission mode. It names an Agent Profile (its Device and its id) for them, or sets them itself; a field it sets wins over the profile. The agent picks its Outcome in its Step Report. With `ask: "person"`, an agent that needs input asks a person in a Gate instead of ending on `needs-input`: "answer" sends the person's note to the same Session, "stop" ends the Step `fail`. | PLAN §3; ADR 3 |
| Agent Profile | A Harness, a model, an effort, a permission mode, CLI Tools and Connections under one name, made on the Agents page of one Device. It belongs to that Device: its identity is the Device and the profile's id, and its name is a label, so two Devices can each have a "builder". An Agent Node names the pair in `profile`, and the editor shows "builder on LE2316". The profile's Device is where the Step runs. When that Device is offline, the Step waits for it: Night Shift never takes another Device's profile with the same label. A Project has no profiles of its own: the Import on upgrade made each one a profile of the importing Device. In a personal Space, every profile of the Person's Devices is usable. In a shared Space, another Person's profile is usable only through an Offer. A Run resolves the profile when it starts, so a later change reaches the next Run, and a rename changes no Flow. A Flow that names a profile on a Device that the Space no longer has does not start: the editor marks the node and asks for another profile. | Agents; ADR 1, ADR 3 |
| Model Profile | A Decider and, optionally, its model under one name, for Decisions and Values decided by a model. Made on the Agents page ("Model profiles") of one Device. Like an Agent Profile, it belongs to that Device: a Decision or a Value names its Device and its id in `profile`, with no fallback to another Device's profile of the same label. A node's own `decider` and `model` still work and win over it. Without a model, each node uses the Decider's default. One page answers "which model": the Agents page. | Node review; ADR 3 |
| Assistant | An agent that helps a Person build a Flow while they edit it: a read-only Session on the agent the Person picks (an Agent Profile with overrides, or a Harness and model), in the Project's Clone. It reads the project and the Flow and only proposes. The editor applies a change to its draft, and only Save saves the Flow, as a new Flow revision. An agent in a terminal reads and saves Flows through `nightshift mcp` instead. The agent: the one the request picks, else "Profile for help" in Settings, else the first profile whose Harness is installed. A Chat on another Harness starts a new Session with the chat so far. The UI says "an agent" ("Suggest with an agent", "Build with an agent", "Ask an agent why"), never "assistant". | Assistant; ADR 2 |
| Suggestion | What the Assistant proposes for one field of a Node or of the Flow, from a "Suggest …" button under or beside the field: the prompt (or its selected part, also Cmd/Ctrl+I), the fields of its Output data, the Variables it sets, an Agent's own outcomes or a Decision's options, a Decision's rules, a Value's expression, a Command's or a Wait's command, a Tool's arguments, the Flow's description and its inputs. A preview first, then Apply or Discard. Undo brings the draft back while nothing changed after it. | Assistant §4.2 |
| Proposal | A new version of the whole Flow from the chat beside the canvas ("Build with an agent"), checked like a saved Flow. The UI calls it a "Proposed change": Show on canvas marks the Nodes and Edges it adds, removes and changes, Apply makes it the draft. "Ask an agent why" on a Run that did not finish opens the chat about that Run, and the fix comes as a Proposal. | Assistant §3, §4.1 |
| Command Node | A Node that runs one shell command in the Worktree. Its Exits map exit codes to Outcomes; without `exits`, 0 is `pass` and any other code `fail`. Its `secrets` name Secrets that the command reads as environment variables of the same name. | PLAN §3, node review §2.4 |
| Exit | One Outcome of a Command Node: an exit code (0–255) and a name. An Exit with the code `"data"` is picked only by the command's data. | Decision Node | A Node that picks one of its Options, which is the Step's Outcome. Its prompt is the question for you, the brief for the model, or a note on the Rules. Later Nodes read `outcome` and `note`. | PLAN §3 |
| Tool Node | A Node that calls one tool of a Connection itself, with arguments from templates, and no model in the loop. The MCP leg of "flow + CLI + MCP", next to the Command Node. `pass` when the tool answers; `fail` when it reports an error, the Connection has no such tool, or does not answer. Later Nodes read `data` (the tool's structured answer, else the JSON its text holds) and `text`. Not a CLI Tool: that is a program an agent may run. | Tool node |
| Option | One of the things a Decision Node can pick, with a name, a description, and (for a Rule) `when`. Each Option has its own Edge. | PLAN §3 |
| Gate | A Decision decided by you: it waits in the Needs-you inbox with its question and its Options, and holds the Run with an Interrupt until you answer. It waits as long as it must, unless it has a Deadline. The palette adds it as "Gate". | PLAN §3 |
| Deadline | When a Gate stops waiting (`deadline` on its Decision Node): a time of day or a date and time (`at`, as a Wait by time reads it), or a number of minutes after the Gate opens (`minutes`). When nobody answered by then, the Gate takes the Option `choose`, and its note says the deadline chose it. The time is fixed when the Gate opens, so a restart keeps it. The UI says "If nobody answers, Night Shift picks keep at 07:00". | Node review §3.1 |
| Branch | A Decision decided by a Rule, as the palette and the canvas name it. The Flow's JSON holds a `decision` Node with `by: "rule"`. | Node review §4 |
| End Node | A Node that ends the Run on purpose, with a result (`status`: `done`, `nothing-to-do` or `failed`) and one line (`message`, a template). No Edge leaves it. The Run ends `finished` (`failed` for a failed End), and the runs list, the Run page and the notification show the result and the line: "Nothing to do: No open issues". A Run an End ended is only run again from a Step, never resumed. In a called Flow, an End ends that Flow: the Call Node ends `pass` (`fail` for a failed End), with the status in `ended` and the line in `end_message`. | Node review §5.3 |
| Lock-screen Gate | A Gate whose Decision Node has `lockScreen: true` ("Can be answered from the lock screen" in the editor). The flow author sets it. It has exactly two options. The answer goes without unlocking the phone or opening the app. Any other Gate opens the app and asks for Face ID or a fingerprint before the answer goes. An answer counts for that one Gate only. The Host alone checks a lock-screen answer: the Gate is marked and open, and the choice is one of its options. | Mobile |
| Rule | A JSONata expression over the same values templates see (`build.data.tests_passed = true and check.exit_code = 0`). On an Option of a Decision decided by a rule, the first Option whose Rule holds is picked, and the one Option without a Rule is the default. On a Value Node made by a rule, the expression's result is the data. No model, no cost. | Decision, Value |
| Value Node | The twin of a Decision Node: a Decision picks a label, a Value makes `data` that matches its Output Schema. A Command Node names Secrets in `secrets`; its Step runs on a Device that has them and reads them there. The Secrets list shows where each is set, what uses it, when it was last set in Night Shift, and when a Step, a connection test or a decider last read it. | Lease | The right of one daemon to write to a database. The daemon takes it at start, keeps it with a heartbeat, and gives it up on a clean stop. A second daemon on the same database refuses to start. Each acquisition has an Epoch one higher than the last. | Lease |

| Parallel branch | The Nodes a Run reaches from one Edge of a Fan-out before its Join. Parallel branches run side by side, step for step, and share the Run's copy of the project. | Join Node | A Node where the Parallel branches of one Fan-out meet. `wait: "all"` goes on when every one arrived, `first` with the first one, and stops the others. Ends `done`; its `data` holds each Parallel branch's data by the Node it came from. | Node review 2026-10 |
| Traversal | One time a Run took an Edge (`EdgeTaken` in the Event Log). Counted per Edge and per scope: the Run's own Flow, each Call, each Item. The Max of an Edge caps its Traversals. | Slice 2 |
| Retry Loop | An Edge back to an earlier Node, bounded by a Max. | PLAN §2 |
| Template Variable | A reference to a value in a prompt or command: a Node output, an Input, a Variable, or a Run field, with an optional JSON path, for example `{{check.log_tail}}`, `{{item.parent.number}}`, `{{vars.tries}}`, or `{{run.branch}}`. | PLAN §3 |
| Template Scope | What a template may read at one place in a Flow: the Inputs, the Variables, each Node's output fields, and the Run's fields. The checks of a Flow and the editor's suggestions read the same scope (`templateScope`), so the editor suggests only what the checks accept. | Architecture review 2026-10 |
| Variable | A named, typed value a Flow keeps while it runs, like a local variable of a function: text, number, yes or no, or JSON (with an optional schema). Each Flow invocation has its own: the Run's top-level Flow, each Call, each Item. | Variables |

| Issue | One problem the validator finds in a Flow. A Flow with an error cannot run. | Slice 2 |

| Quick Run | A Run of a one-node Flow made from a prompt, without a saved Flow. | Slice 2 |

The runner's one entry (`take`, `graph/runner.ts`). | Run core |
| Run action | What a person does to a Run: stop it, answer its Gate, send its Signal, move it, resume it, restart its Step, or run it again. Which ones a Run allows is one rule, from its status and whether this computer walks it: every screen offers only those, and Night Shift refuses the rest with a sentence that says why and what to do. On a Run another Device walks, a stop, an answer, a Signal and a move travel to its Walker as Commands. Only the Walker resumes, restarts or runs it again. | Architecture review (O4) |

## Run status

| Term | Meaning |
|------|---------|
| running | A Step runs, or the Run is between Steps. |
| waiting | A Gate waits for a person in the Needs-you inbox. |
| sleeping | A usage limit or a network failure: a timer continues the same Session. |
| finished | The Run reached `pass` or a Decision Option with no Edge left to take, or an End Node with `done` or `nothing-to-do`. |
| stopped | A person stopped the Run. |
| failed | A Step errored, a `fail` or `needs-input` had no Edge, a Retry Loop hit its Max, or an End Node with `status: "failed"` ended it. |
| result | Not a status: how the End Node that ended the Run says it came out (`done`, `nothing-to-do`, `failed`). A `nothing-to-do` Run is `finished` and shows "Nothing to do". |
| interrupted | The daemon stopped while a Step ran. The next daemon resumes it on its own a few seconds after it starts, unless its end reason says why not. |

| RunResumed | A person resumed a Run, or the daemon did after a restart (`by: "daemon"`). `action` says when it was more: `restart` (a person restarted the running Step) or `rerun` (a person ran the Run again from a Node). |
| StepStarted | A Step began a Visit of a Node. |
| StepReopened | A resume continued an Agent Step's Session in place. |
| StepEnded | A Step ended with an Outcome and its Outputs. |
| SessionStarted | A harness Session began for an Agent Step. |
| HarnessSessionAssigned | The Harness reported its own session id. |
| SessionUsage | What a running Session has spent so far, at most every 5 seconds. Only some Harnesses report it while they work. A Session that ends without a Cost keeps the last total. |
| SessionEnded | A Session ended, with its Cost and where it came from (reported or estimated). |
| EdgeTaken | The Run followed an Edge to the next Node. |
| StopRequested | A person asked to stop the Run. |
| GateOpened | A Gate put its question in the Needs-you inbox. |
| WaitStarted | A Step began a Wait: why, until when (none for a Signal with no timeout), and which Signal. |
| WaitEnded | The Wait is over: the timer, a person, or a Signal. |
| RunEnded | The Run finished or failed, with the reason. After an End Node, also its result and its line. |
| RunWarned | A Warning about the Run, with the Step it is about. |
| ScheduleFired | A Schedule came due and started its Run, or failed to start it. |
| ScheduleSkipped | A Schedule came due but did not start: too late, or its previous Run still runs. |

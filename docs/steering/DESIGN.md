# Night Shift Design Guidelines

> Generated by `steer-design`. Refine this document as the design system evolves — do not regenerate from scratch.

Last updated: 2026-11-11

## Design Principles

1. **Show the facts, not a mood** — Every status on screen comes from a fact the user can open: an event, a step's output, a check. No spinner without a session behind it.
2. **The gate is the product** — The "Needs you" inbox is the most important screen. It shows one gate at a time, in focus, from a queue of the open gates of every Space you are in: Now, then Today, then When you have time. In each, the gates with a deadline come first, the earliest first. The others follow, the oldest first. A row of bars shows the queue in urgency colours. Previous, Skip for now and Next (and the arrow keys) move through it. The gate starts with an urgency band (level, deadline, what Night Shift picks then), then the title, the situation, the links as buttons, and the recommendation. The answer follows: the options in their own colour, the recommended one first. The picked option gets a tinted background. Then a context field opens, and Send (or Enter) sends it. What is done and the details fold away, unless the gate has no brief. Answered is a second view, by day, for 90 days: each row shows the option in its colour, who chose it, and the run now. A row opens the whole gate in a Sheet. Home shows what needs you, and what came out. To resolve a gate takes two actions: pick a choice, then send. Nothing goes out by accident.
3. **Calm by default** — An unattended run is quiet. The UI shows only changes that need a person. Noise goes to the transcript. A notification goes out only for a gate, a finished run, a failed run or a step that waits for an offline device. It goes only to the screens the person chose, outside their quiet hours.
4. **Night Shift's words, the flow's content** — The UI names what Night Shift does in the glossary's words: flow, run, step, Gate. The words of a method or a domain (Epic, Trace, a lead) show only as the content of a flow: its names, prompts and outputs. No screen belongs to one method.
5. **Readable for anyone** — No terminal metaphors. A session is a transcript. A takeover is a button that copies a command.

### Overview lists

An overview shows **at most 5 rows** in a list or table: the Failed lane and Latest reports on Home, the tabs under a project page's chart (Flows, Failures, Gates, Spend), and every tab of a details dialog.

- One number for all of them: `OVERVIEW_ROWS` in `apps/web/src/features/dashboard/overview.ts`. Do not add a limit per list.
- Show the top 5 for the list's question: newest first, the most runs, the highest cost. Say which in the hint ("The last 5, newest first", "The top 5, the most runs first").
- The full list is one link away: a section action ("Flows", "All runs") or the dialog footer. Under a cut list in a dialog, `MoreRows` says how many rows it leaves out.
- Pages whose job is the full list (the runs page, the inbox, the flows page) do not use this limit. Neither does Home's Running now lane: what runs now shows in full. A project's runs page shows 15 runs to a page.

### A project's page

A project's page shows where each of its flows still needs you (`docs/research/dashboards-2026-11.md`). Keep its shape:

- One range for the whole page, on top: 7, 30 or 90 days, in the URL (`?range=30`). A day runs from midnight to midnight on your clock. No section has a range of its own.
- One card of numbers: **Needed you without a plan**, **Needed you as planned**, **On its own** (how many flows are at that level), and **How N runs ended** as one bar. The first two count each time you stepped in, not each run. Each says how it moved against the same days just before. That is not a choice.
- **Details** next to a number opens its details dialog at the page's range.
- Under it, one card with one row per flow (see Flow health). The flows that needed you most without a plan come first.
- The page shows no spend of its own. **Spend** in the heading opens the Spend page at the page's range. Cost stays only as evidence of a flow: what a finished run costs, and what a useful result costs.
- A test run counts only in the spend. Every other number leaves it out (`isTestRun`, one rule for every number). So does the sidebar's runs donut. The run page and every run list show a **Test run** badge. On the phone, the Runs chips and the Watch numbers leave it out, and the cost caption names it ("Of 8 runs and 1 test run").
- An older Host sends no level and no planned split: a dash.
- Setup does not go on this page. Its other pages sit under the project in the sidebar.

### Home

Home is a note over every project that you read top to bottom. It guards the flows that nobody watches (`docs/research/dashboards-2026-11.md`). Keep its shape:

- One narrow column (`max-w-2xl`), sentences before numbers. No range, no cards of numbers, no spend.
- The heading says how many flows need a look: "3 flows need a look." or "Every flow did its work." When you were here before, it splits the new ones: "1 new flow needs a look. 2 still do." The line above it says when you last looked.
- Under the heading, one sentence with the number of times your flows needed you without a plan this week, against last week, and one small bar per week for 12 weeks. The number follows the week, not your last look.
- Until this computer has an agent, **Get started** sits under the heading. Its rows: An agent (**Set up**), A decider (**Choose**, optional), and A project (**Add project**, no folder needed). A row that is done shows a check. Once the card shows, it stays until you leave Home. The setup on Home does not open the new profile. **Later** hides the card until the next session.
- **Needs a look** holds one row per flow that left its usual range: its last runs failed, its last runs found nothing to do, or its last run cost more or took longer than every run before. Nobody sets a threshold. A row is state, not news: it stays until the flow is back in its range.
- **Look** opens the flow in a Sheet at the side: what is unusual, the usual range against now, and the links to the run and the flow. For a failed run, **Ask an agent** reads the run and says what went wrong. It changes nothing.
- **Looked at it** folds the row to one line ("You looked at … at 08:14"). It comes back as a row when its signal starts again. A flow that left the list since your last look says so once: "… is back to normal."
- Only what is new since your last look gets a **New** badge. Night Shift keeps your last look in this browser.
- **What came out** lists the newest report of each flow from the last 7 days, the new ones first. The reports from before your last look fold behind one line. A row opens the run page at its report. Night Shift never pushes a report.
- Home has no list of Gates and no list of runs at work. The inbox holds the Gates. A run that works longer than usual is a Needs a look row.
- A test run does not count on Home.
- An older Host sends no watch: one line asks to update Night Shift, and What came out still shows.
- A run page opens at its report when the run ended with one and the link names no step.

### Spend

Spend is the page for the money of a Space, for the person who pays (`docs/research/dashboards-2026-11.md`, Q9). It sits under the Inbox in the sidebar. Keep its shape:

- One range for the whole page, in the heading: 7, 30 or 90 days, in the URL (`?range=90`). It opens at 30 days.
- Four cards on top: **Spent** against the same days before, with one bar per day, **Steady flows**, **Hard to predict**, and **You could save**.
- **How predictable each flow is** has one row per flow that cost money, the most spend first. A strip shows what its runs cost against a usual run of that flow. A usual run is the median of its finished runs with a known cost. Every strip has the same scale, 0× to 6× a usual run, so a short strip means a steady cost.
- **Cost is** says **Steady**, **Varies** or **Hard to predict**. Night Shift reads it from the runs. Nobody sets a threshold. A flow with fewer than 3 such runs has none.
- A row opens in place: what each step costs per run, what stands out on a step, and the ways to save on that flow.
- The flows that cost nothing share one row. So do the quick runs. The last row is the total.
- **Ways to save** lists changes that the runs show, the biggest first: runs that did not finish, runs that found nothing to do, and runs that cost over twice a usual run. A run counts under one of them only. Each card says what the change saves, how many runs show it, and opens the newest of those runs and the flow.
- The page never shows a saving that the runs do not show. It does not guess what another model or a removed step saves.
- A test run counts in the spend. It is not in a usual run or in a way to save.
- An older Host cannot send the page: one alert asks to update Night Shift.

### Knowledge

A project's Knowledge opens on an overview. Five child pages hold the details: Review, Files, Sources, Questions and Map. Each has its own address (`/projects/<id>/knowledge/files`).

- **The toolbar breadcrumb is the way between the pages.** On a child page it reads Home › project › Knowledge › Files. Knowledge leads back to the overview. The current step is a menu of the five pages. Do not add tabs, a breadcrumb inside the page, or sidebar items for them.
- **The overview** has the search on top, then a card for what waits for you and a card per child page. A search replaces the cards until you clear it. Each card shows the facts that matter and at most 5 rows (see Overview lists). A row opens its child page.
- **Review** shows one task at a time, in one column, `max-w-3xl`: a source that fails, a step's learnings, a question that found nothing, files no run used. Keys: K keeps, D deletes, S puts off. A row in "Next" brings that task forward.
- Keep and Delete leave the queue at once and go out after 5 seconds. The toast has Undo. Leaving Knowledge sends them. The queue stays while you move between the child pages.
- A note close to another note shows that note's text under it, with "Close to a kept note", "Close to a note that also waits" or "Close to a note here". The words say "close" and nothing more: only a person can tell whether two notes repeat or disagree. The phone does not show them.
- "Not important" and "Keep syncing them" are remembered in this browser. A learning is never dismissed: a person keeps or deletes it.
- **Files** has the search on top, then every file by folder: folders on the left, the files of the chosen folder on the right. Each side scrolls on its own. A search replaces the folders until you clear it.
- **Sources** lists where the files come from. **Questions** lists what agents searched for, with the test of search on top when questions are marked.
- **Map** shows files, topics, questions and learnings as a graph. Search shows what an agent would find. An item shows what it connects to in the panel beside the map. "Not a topic" on a topic takes it off the Map for the whole Space, and a menu shows it again. "Show on map" on a task opens the Map at that item (`?node=`). "Review it" on a learning goes back to Review with that learning first.
- **Words.** The page that lists files is "Files". Not "What agents know": a label names what you see. The Map shows "items", because a Node is part of a flow. A person marks questions, so the page says "marked questions", not "question set".

### Setup pages (Agents, Secrets, Settings)

What you configure once reads like the Settings page:

- One column, `max-w-4xl`, a `PageHeading`, then one `PageSection` per kind. A section's add button sits in its header.
- A list is an `ItemGroup` of outline `Item`s. A row that opens something is a link (`render={<Link />}`), so it hovers and opens in a new tab.
- A pick opens its detail in place. The breadcrumb leads back ("Agents › builder"). No list beside the detail.
- What this computer has but does not use yet sits at the end of the list it joins, as a dashed row with one action ("Add profile", "Add tool"). Not in a banner on top.
- Secrets have their own page in the main menu: Command nodes use them too, not only agents.
- Secrets have two pages. The computer's page (under the computer in the Settings menu) lists the Personal secrets and this computer's. The Space's page (under Space in the Settings menu) lists each project's secrets and the secrets on your other devices.
- The computer's page leaves out a missing name when each flow that uses it gets it from its project.
- A project's Secrets are a page under the project in the sidebar, beside Knowledge. They are setup, so they do not go on the project's page.
- A secret on another of your devices has the same row menu as your own: Move to Personal, Move to a project…, Remove from <device>. That device does the work. When it is offline, the toast says so and when to try again. Its profiles stay read-only here.
- A move into a project ends with a toast whose action opens that project's Secrets page.

### Devices

The Devices page shows the Space you work in, around its Host:

- The Space's name as the heading. "Pair a device" sits on the right, only where this computer keeps the Space as its Host.
- One "Next step" card on top: the first open step to make the Space work across devices. In your personal Space: Be a Host, another computer, your phone. In a shared Space: invite a member, offer a profile, your phone. "Not now" moves on to the next step. The card goes once every step is done.
- The Host as a card, with your phones on it as chips. When this computer cannot reach the Host, the card turns red and says since when, with "Check the connection".
- The computers as a grid of cards: status, up to two active runs, then "and N more", and how many projects and Offers each has. A card has at most one action of its own ("Be a Host", "Offer a profile", "Pair again").
- A pick opens its detail in a Sheet over the page (`?device=`), so the page stays in view.
- While it loads, a skeleton in the shape of the page. An error says what to check and has "Try again".

### Details dialogs

A stat card or a table row can open a details dialog (`apps/web/src/features/dashboard/details.tsx`). Flow health set the shape. Every details dialog follows it:

- A header with the trail ("project › Runs") and a title.
- `DetailsTabs`: Overview first, then one tab per view (a breakdown per flow or project, the latest or top rows). A tab can carry a count badge for what needs attention (problems, open runs, waiting Gates).
- One range toggle on the right of the tabs. It drives every tab.
- Overview: 3 to 6 `Stat` cards, then one chart. Flow health has 6, in two rows of three. Other tabs: one list or table, at most 5 rows (see Overview lists).
- Each tab has its own empty state. A footer links to the full page.

### Flow health

Flow health is the card of flows on a project's page, one row per flow. Keep its shape:

- Columns: Flow, Last runs, **Needed you without a plan**, Per finished run, Needs a look. Under the flow's name: its level (**You decide**, **You check**, **On its own**) and since when. A flow with fewer than 3 ended runs has no level yet.
- The level is measured from the flow's last 10 ended runs: You decide when you stepped in on more than half, On its own when on none, else You check. Nobody sets it.
- Needed you without a plan shows the count, the count of the days before, and one small bar per week for 12 weeks. Its tooltip adds the planned times.
- Per finished run is a box plot of what a finished run costs, with the median under it.
- A row opens in place (a Collapsible), one at a time. Left: History, Why runs did not finish, Latest runs. Right: its signals, **Why it needed you** (Without a plan, As planned, each with the Gate's question), **Where the work landed**, Per useful result, and the time of a finished run. **All details** opens the details dialog.
- **Where the work landed** has a thin segmented bar for the work and one for the choices: 8px, rounded parts, a 2px gap, one part per rung in ladder order. A line next to each bar gives the shares: "Sonnet 78% · Opus 19% · You 3%". It names the 3 biggest rungs and how many more there are.
- Its tooltip gives each rung with its count and the cost of one landing, every try before it included. It adds how often a decider was not sure enough: "A decider was not sure enough in 6 of 50 Decisions."
- Count a landing in times ("32 of 41 times") or Decisions, never in steps: each try of a cascade is a step. Show a cost per landing, never a sum over a flow's rungs: a Subflow's landing holds the cost of the Agent inside it.
- The rungs are named the same everywhere (`@nightshift/client` `ladderParts`): the tier, or Agent, Subflow, Decider, Rule. A person is always "You". "Its deadline" is a rung of its own. "Nowhere" is the rung when nothing held.
- The rung colors are the `--ladder-*` tokens. The text next to a bar stays in text colors.
- An older Host sends no ladders: a dash, and the tooltip says "Update Night Shift to see where the work landed."
- A test run is not in a row: not in its last runs, its numbers or its latest report. The details dialog counts it only in the spend. "Total spent" says how many test runs it holds.

**All details** in an opened row opens the flow's details dialog. Its tabs: Overview, Ladders, Metrics, Cost, Problems, Runs.

- **Ladders**: a card per ladder (rung, share, count, cost each, the not-sure line under Choices), then the 5 nodes that landed most, each with its own bar.
- **Metrics**: a `Select` picks the metric (Q32). Four `Stat` cards: Total, Per run, Latest, Runs. Then three small charts on one day axis, in this order: the metric per run, Spent, Needed you. A hover on one day shows it in all three. Then the Metrics table: every metric with its runs, total, average and latest value.

## Copy

The rules are in `AGENTS.md` ("UI copy"). This is how to apply them. The
Settings page (bbc8b651) set the bar. A copy pass over the whole web app
followed on 2026-10-30.

**Balance.** UX copy decides what to say: lead with the action or the
result, and say what happens next. STE (ASD-STE100, relaxed dictionary)
decides how to say it: short common words, active voice, simple present,
one idea per sentence. Aim for plain and friendly. A sentence that obeys
STE but no longer speaks to "you" went too far.

**Cut first, rewrite second.** Check each string in this order:

1. Does it repeat the label or the title? Delete it.
2. Does it explain how Night Shift works inside? Delete it.
3. Does the placeholder, unit, example or icon already say it? Delete it.
4. Is it decoration or a joke? Delete it.
5. What stays: a description in 1–2 sentences, a hint in 1, max 20 words a
   sentence. Keep limits, risks and what is lost.

**Before and after** (from the Settings page):

| Before | After |
| --- | --- |
| "How many runs can work at the same time. Extra runs wait their turn." (Max concurrent runs) | "More runs wait their turn." |
| "A run stops when it has spent this much. Resume it to spend as much again. Leave it empty for no budget." (placeholder: "No budget") | "The run stops at this amount. Resume it to spend as much again." |
| "This computer does not go to sleep while a run on it works or waits for a timer. A run that waits at a Gate does not keep it awake." | "Stay awake while a run works or waits for a timer. A run at a Gate lets it sleep." |
| "Each run works in its own copy of the project, on its own branch. Night Shift can remove old ones for you." | "Remove what old runs leave on this computer." |
| "A run waits for your answer." (under "A Gate waits for you") | (none) |
| "Light or dark, as macOS is." / "For the night." / "For the morning after." | (none) |

**Any domain.** Night Shift is domain-neutral. Examples, placeholders and
empty states span research, monitoring, outreach, operations, content and
code. They never default to code or pull requests. Say "agent", not "coding
agent", and "project", not "repository", unless git itself is meant. In an
example, a Gate is a fallback or an approval before an act that cannot be
undone, not a review of every result.

**In code.** A field component takes an optional `description` and renders
nothing without it (`apps/web/src/features/settings/components/setting-fields.tsx`).
No empty `FieldDescription` or `ItemDescription` in the DOM. Copy that
comes from a package (harness notes, run end reasons, flow issues) follows
the same rules: fix it at its source, not in the app.

**Review.** In a pull request that adds or changes UI text, read every new
string aloud. If you can drop a sentence and the person still knows what
to do, drop it.

## UI States Required

- **Default** — the base state
- **Loading** — an async operation runs
- **Error** — something failed (inline, not modal, unless data is lost)
- **Empty** — no data to show, with the next action
- **Disabled** — the action is not available here
- **Focus** — keyboard navigation is active (must be visible)
- **Stale** — the cached index is older than the poll interval. Show the age

## Accessibility Standards

- Minimum contrast ratio: 4.5:1 for body text, 3:1 for large text and UI components
- Every interactive element works from the keyboard, with a visible focus indicator
- Every image has descriptive `alt` text. Decorative images use `alt=""`
- Color is never the sole means of conveying information. A status always has a label.
- Every form input has a `<label>` element, not only placeholder text
- Live regions announce a new gate and a finished run.
- Light and dark both ship. Every token has a value in both sets.

## Responsive Behavior

The product is a desktop app first. The web UI must still work in a narrow window. The phone app is a second screen for the inbox, runs and Start run. It uses React Native Reusables, not the web UI (see `docs/research/mobile.md`).

| Breakpoint | Width | Layout behavior |
| --- | --- | --- |
| Narrow | < 768px | Single column. Sidebar collapses to a menu. |
| Medium | 768–1280px | Sidebar plus one content column. |
| Wide | > 1280px | Sidebar, content, and a detail pane (transcript or gate). |

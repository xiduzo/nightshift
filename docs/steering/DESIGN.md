# Night Shift Design Guidelines

> Generated by `steer-design`. Refine this document as the design system evolves — do not regenerate from scratch.

Last updated: 2026-10-10

## Design Principles

1. **Show the facts, not a mood** — Every status on screen is derived from a fact the user can open: an event, a pull request, a check. No spinner without a session behind it.
2. **The gate is the product** — The "Needs you" inbox is the most important screen. A gate shows the question, the context, and the choices on one card. Resolving one takes one action.
3. **Calm by default** — An unattended run is quiet. The UI surfaces only changes that need a person. Noise goes to the transcript.
4. **Same words as the method** — The spec tree uses the method's own terms (Epic, Feature, Trace for WTF). The pipeline uses Night Shift terms (Flow, Step, Gate). Never mix the two on one card.
5. **Readable for a Product Owner** — No terminal metaphors. A session is a transcript. A takeover is a button that copies a command.

## Tokens

Tokens live in `packages/ui/src/styles/globals.css` as CSS custom properties in oklch, with a light `:root` set and a `.dark` set. Tailwind reads them through `@theme inline`.

### Color

| Token | Value (light / dark) | Use |
| --- | --- | --- |
| `--background` / `--foreground` | `oklch(1 0 0)` / `oklch(0.145 0 0)` | Page |
| `--card` / `--card-foreground` | `oklch(1 0 0)` / `oklch(0.205 0 0)` | Gate cards, session cards |
| `--primary` / `--primary-foreground` | `oklch(0.205 0 0)` / `oklch(0.87 0 0)` | The one primary action per view |
| `--secondary`, `--muted`, `--accent` | `oklch(0.97 0 0)` / `oklch(0.269–0.371 0 0)` | Surfaces and hover |
| `--destructive` | `oklch(0.58 0.22 27)` / `oklch(0.704 0.191 22.216)` | Halt, reject, delete |
| `--border`, `--input`, `--ring` | `oklch(0.922 0 0)` / `oklch(1 0 0 / 10%)` | Edges and focus |
| `--chart-1` … `--chart-5` | blue scale | Cost and run history charts |
| `--sidebar-*` | mirrors the page set | Project navigation |

The palette is neutral. Status colors (running, blocked, needs you, verified) are not yet defined. Add them as tokens before any screen hardcodes a color.

## Component Patterns

| Pattern | Component | Notes |
| --- | --- | --- |
| Primary action | `packages/ui/src/components/button.tsx` | One primary button per view |
| Gate card, session card | `packages/ui/src/components/card.tsx` | Question, context, choices |
| Chat transcript | `message.tsx`, `message-scroller.tsx`, `bubble.tsx`, `attachment.tsx`, `marker.tsx` | Project chat and session transcript share these |
| Forms | `input.tsx`, `input-group.tsx`, `textarea.tsx`, `label.tsx`, `checkbox.tsx` | Settings, project config |
| Menus | `dropdown-menu.tsx` | Per-row actions |
| Feedback | `sonner.tsx`, `tooltip.tsx`, `skeleton.tsx`, `empty.tsx` | Toasts for events, skeletons while facts load, empty states with a next step |

Pipeline board, spec tree, and gate inbox components do not exist yet. Build them in `packages/ui` from the primitives above.

## UI States Required

- **Default** — the base state
- **Loading** — async operation in progress
- **Error** — something went wrong (inline, not modal, unless data is lost)
- **Empty** — no data to show, with the next action
- **Disabled** — action not available in context
- **Focus** — keyboard navigation active (must be visible)
- **Stale** — the cached index is older than the poll interval; show the age

## Accessibility Standards

- Minimum contrast ratio: 4.5:1 for body text, 3:1 for large text and UI components
- All interactive elements keyboard-navigable with visible focus indicator
- All images have descriptive `alt` text; decorative images use `alt=""`
- Color is never the sole means of conveying information. A status always has a label.
- Form inputs have associated `<label>` elements (not just placeholder text)
- Live regions announce a new gate and a finished run.
- Light and dark both ship. Every token has a value in both sets.

## Responsive Behavior

The product is a desktop app first. The web UI must still work in a narrow window.

| Breakpoint | Width | Layout behavior |
| --- | --- | --- |
| Narrow | < 768px | Single column. Sidebar collapses to a menu. Board becomes a list. |
| Medium | 768–1280px | Sidebar plus one content column. |
| Wide | > 1280px | Sidebar, content, and a detail pane (transcript or gate). |

# Night Shift Design Guidelines

> Generated by `steer-design`. Refine this document as the design system evolves — do not regenerate from scratch.

Last updated: 2026-10-21

## Design Principles

1. **Show the facts, not a mood** — Every status on screen is derived from a fact the user can open: an event, a pull request, a check. No spinner without a session behind it.
2. **The gate is the product** — The "Needs you" inbox is the most important screen. It lists the open gates of every Space you are in on the left, grouped by project, like the Agents page. The open gate shows what happened on the left, and its links, choices and note on the right. The right side stays in place while you read. Resolving one takes two actions: pick a choice, then send. Nothing goes out by accident.
3. **Calm by default** — An unattended run is quiet. The UI surfaces only changes that need a person. Noise goes to the transcript. A notification goes out only for a gate, a finished run, a failed run or a step that waits for an offline device, on the screens the person chose, outside their quiet hours.
4. **Same words as the method** — The spec tree uses the method's own terms (Epic, Feature, Trace for WTF). The pipeline uses Night Shift terms (Flow, Step, Gate). Never mix the two on one card.
5. **Readable for a Product Owner** — No terminal metaphors. A session is a transcript. A takeover is a button that copies a command.

## Tokens

Tokens live in `packages/ui/src/styles/globals.css` as CSS custom properties in oklch, with a light `:root` set and a `.dark` set. Tailwind reads them through `@theme inline`.

| Token | Value (light / dark) | Use |
| --- | --- | --- |
| `--background` / `--foreground` | `oklch(1 0 0)` / `oklch(0.145 0 0)` | Page |
| `--card` / `--card-foreground` | `oklch(1 0 0)` / `oklch(0.205 0 0)` | Gate cards, session cards |
| `--primary` / `--primary-foreground` | `oklch(0.205 0 0)` / `oklch(0.87 0 0)` | The one primary action per view |

### Overview lists

An overview shows **at most 5 rows** in a list or table. This covers the sections on Home and on a project page (Recent runs, What the night produced, Up next, Flow health), and every tab of a details dialog.

- One number for all of them: `OVERVIEW_ROWS` in `apps/web/src/features/dashboard/overview.ts`. Do not add a limit per list.
- Show the top 5 for the list's question: newest first, the most runs, the highest cost. Say which in the hint ("The last 5, newest first", "The top 5, the most runs first").
- The full list is one link away: a section action ("Flows", "All runs") or the dialog footer. Under a cut list in a dialog, `MoreRows` says how many rows it leaves out.
- Pages whose job is the full list (the runs page, the inbox, the flows page) do not use this limit.
- Recent runs on Home pages through every run, 5 to a page, instead of a cut list. It needs no hint and no "All runs" link. A project's runs page shows 15 runs to a page.

### Details dialogs

A stat card or a table row can open a details dialog (`apps/web/src/features/dashboard/details.tsx`). Flow health set the shape. Every details dialog follows it:

- A header with the trail ("project › Runs") and a title.
- `DetailsTabs`: Overview first, then one tab per view (a breakdown per flow or project, the latest or top rows). A tab can carry a count badge for what needs attention (problems, open runs, waiting Gates).
- One range toggle on the right of the tabs. It drives every tab.
- Overview: 4 `Stat` cards, then one chart. Other tabs: one list or table, at most 5 rows (see Overview lists).
- Each tab has its own empty state. A footer links to the full page.

## UI States Required

- **Default** — the base state
- **Loading** — async operation in progress
- **Error** — something went wrong (inline, not modal, unless data is lost)
- **Empty** — no data to show, with the next action
- **Disabled** — action not available in context
- **Focus** — keyboard navigation active (must be visible)
- **Stale** — the cached index is older than the poll interval; show the age

## Accessibility Standards

- Minimum contrast ratio: 4.5:1 for body text, 3:1 for large text and UI components
- All interactive elements keyboard-navigable with visible focus indicator
- All images have descriptive `alt` text; decorative images use `alt=""`
- Color is never the sole means of conveying information. A status always has a label.
- Form inputs have associated `<label>` elements (not just placeholder text)
- Live regions announce a new gate and a finished run.
- Light and dark both ship. Every token has a value in both sets.

## Responsive Behavior

The product is a desktop app first. The web UI must still work in a narrow window. The phone app is a second screen for the inbox, runs and Start run. It is built from React Native Reusables, not from the web UI (see `docs/research/mobile.md`).

| Breakpoint | Width | Layout behavior |
| --- | --- | --- |
| Narrow | < 768px | Single column. Sidebar collapses to a menu. Board becomes a list. |
| Medium | 768–1280px | Sidebar plus one content column. |
| Wide | > 1280px | Sidebar, content, and a detail pane (transcript or gate). |

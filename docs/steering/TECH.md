## Architecture

- **Pattern:** Ports and adapters. The engine and the runner depend on interfaces. Connectors, harnesses, and transports are adapters behind them.
- **Module structure:** A Bun workspace. `apps/server` is the daemon (Hono, oRPC, Better Auth, SSE). `apps/web` is the UI. `apps/desktop` is the Electrobun shell and holds no logic. `packages/db` owns the schema. `packages/api` owns the oRPC contracts. Planned: `packages/config`, `packages/methods`, `packages/engine`, `packages/runner`, `packages/connectors`. See `docs/PLAN.md`.
- **State management:** The server stores durable facts in libsql and appends every change to an event log. The UI derives status from facts and subscribes to the event log over SSE through TanStack Query.
- **Data flow:** UI → oRPC → engine → runner or connector → facts + event → SSE → UI. The runner speaks an NDJSON event protocol. In v1 the transport is in-process.
- **Method execution:** Every method step runs as a harness session through a TanStack AI harness adapter. The runner materializes the method's skill pack into a per-run plugin directory. The orchestrator step returns a schema-validated decision.

## Key Constraints

- Store facts, never status. Derive status in a query or a view. Append an event for every change.
- The engine owns order, retries, locks, and gates. A model decision is a schema-validated value. Never let a model reorder or add work.
- Every external I/O goes behind an interface in `packages/connectors` or `packages/runner`. No `gh`, `git`, or harness call outside an adapter.
- Never delete a dirty worktree. Garbage collection skips any tree with uncommitted changes.
- Cap concurrent sessions per runner. The cap is configuration, not a constant.
- A step runs in one repo. A cross-repo change is two steps.
- Put a tenant id on every row. No query crosses a workspace.
- Read a method's own config file (for example `.wtf/config.json`). Never copy it into `.nightshift/project.json`.
- Validate `.nightshift/project.json` and `method.json` with a published Zod schema. A schema error is a doctor finding, not a warning.
- The app holds secrets in the OS keychain. Prefer the CLI's own login over a stored token.
- A step that runs unattended ends with a structured report. It never waits on a person mid-session.
- No PTY. A session is a structured event stream.

## Commands

```bash
# Install
bun install

# Apply the schema to local.db
bun run db:push

# Dev (web + server, hot reload)
bun run dev

# Dev desktop shell
bun run dev:desktop

# Run tests
bun test

# Lint + format
bun run check

# Type-check
bun run check-types

# Build (desktop last)
bun run build

# Git hooks
bun lefthook install
```

## Code Conventions

- **Naming:** PascalCase components and types, camelCase functions and variables, kebab-case file names.
- **File structure:** One workspace package per bounded context. Inside a package, group by feature, not by kind.
- **Test files:** Colocated `*.test.ts` next to the module. Bun's test runner.
- **Imports:** Workspace packages by name (`@nightshift/db`). No relative imports across packages.
- **Formatting:** Biome. The pre-commit hook formats staged files.
- **Environment:** varlock schemas in `.env.schema`. Generated types, never `process.env` by hand.
- **Prose:** Durable docs follow the ASD-STE100 style of the WTF skills. Short sentences, active voice, one idea per sentence.

## Architecture Decision Records

| Decision | Rationale | Date |
| --- | --- | --- |
| Electrobun, not Tauri | Bun is the main process, so the daemon runs in-process with no sidecar and no IPC seam. | 2026-10-10 |
| libsql, not Postgres | Embeddable now, replicable later, so local mode and server mode share one schema. | 2026-10-10 |
| oRPC, not tRPC | Gives an OpenAPI surface for free. Remote runners and integrations call it later. | 2026-10-10 |
| Every step on a harness | Skills already assume a coding agent's tool belt. Re-implementing it on a raw model is waste. | 2026-10-10 |
| Stateless orchestrator | A resident orchestrator agent is a single point of failure. Short checkpoint steps that read durable state are not. | 2026-10-10 |
| Durable facts, derived status, event log | Removes the class of bugs where a late hook overwrites a state. | 2026-10-10 |
| CLI-first connectors | `gh` and `acli` already hold the user's login and match what the skills call. MCP per vendor when a CLI falls short. | 2026-10-10 |
| Runner protocol from day one | Streaming, approval round-trips, and cancel are the messages that hurt to extract later. | 2026-10-10 |
| Better Auth always | One identity model. Local mode auto-creates one user. | 2026-10-10 |
| Config as a repo file | Versioned, reviewable, diffable. Configuration drift was the main pain in the tool this replaces. | 2026-10-10 |

Full ADRs go in `docs/adr/` when a decision needs more than one line of rationale.

## Known Pain Points

- `@tanstack/ai` moves fast (0.39 → 0.68 in a few months). Pin exact versions and upgrade on purpose.
- Electrobun packaging needs a static web build of TanStack Start. Not yet verified.
- The TanStack AI sandbox middleware inside an Electrobun main process is not yet verified.
- `drizzle-orm` is a release candidate.

## Architecture

- **Pattern:** Ports and adapters. The engine depends on interfaces. Harnesses and decider providers are adapters behind them.
- **Module structure:** A Bun workspace. `apps/server` is the daemon (Hono, oRPC, Better Auth, SSE). `apps/web` is the UI. `apps/desktop` is the Electrobun shell and holds no logic. `packages/db` owns the schema. `packages/api` owns the oRPC contracts. Planned: `packages/flows`, `packages/engine`, `packages/agents`. See `docs/PLAN.md`.
- **State management:** The server stores durable facts in libsql and appends every change to an event log. The UI derives status from facts and subscribes to the event log over SSE through TanStack Query.
- **Data flow:** UI → oRPC → engine → agents (harness or tool) → facts + event → SSE → UI. Everything runs in-process.
- **Harness adapters:** `packages/agents/src/adapter-session.ts` runs every Agent step as one TanStack AI session: it owns the sandbox in the worktree, the `chat()` call, the translator, the step report and the abort. One file per harness (`claude-code.ts`, `codex.ts`, `opencode.ts`, `acp.ts`, `grok-build.ts`) holds only a `HarnessSpec`, a TanStack adapter factory and a raw-message observer.
- **Flow execution:** A flow is a JSON file in `.nightshift/flows/`, validated by a zod schema. Every Agent node runs as a harness session through a TanStack AI harness adapter and names a skill the harness already has. A Decision node picks one of its options: you (a Gate), a rule (a JSONata expression over the run's values), or a model whose pick is checked against the options.

## Key Constraints

- Store facts, never status. Derive status in a query or a view. Append an event for every change.
- The engine owns order, retries, loop limits, and gates. A model decision is a schema-validated label. Never let a model change the graph.
- Every loop in a flow has a maximum count. The validator refuses a flow with an unbounded loop.
- Every external I/O goes behind an interface in `packages/agents` or `packages/engine`. No `gh`, `git`, or harness call outside an adapter.
- Never delete a dirty worktree. Garbage collection skips any tree with uncommitted changes.
- Cap concurrent sessions. The cap is configuration, not a constant.
- A step runs in one repo. A cross-repo change is two steps.
- Put a tenant id on every row: `space_id`, the Space (a Better Auth organization). No query of a person crosses a Space. Only background work (the walk, recovery, the scheduler) reads every Space, and it writes each row with its own Space.
- Validate every flow file with the published zod schema before a run starts. A schema error stops the run.
- The app holds secrets in the OS keychain. Prefer the CLI's own login over a stored token.
- A step that runs unattended ends with a structured report. It never waits on a person mid-session.
- No PTY. A session is a structured event stream.

## Commands

```bash
# Install
bun install

# Apply the schema to the dev database (.nightshift-dev/)
bun run db:push

# Dev (web + server, hot reload)
bun run dev

# Dev desktop shell
bun run dev:desktop

# Run tests
bun test

# Lint + format
bun run check

# Type-check
bun run check-types

# Build (desktop last)
bun run build

# Git hooks
bun lefthook install
```

## Code Conventions

- **Naming:** PascalCase components and types, camelCase functions and variables, kebab-case file names.
- **File structure:** One workspace package per bounded context. Inside a package, group by feature, not by kind.
- **Test files:** Colocated `*.test.ts` next to the module. Bun's test runner.
- **Imports:** Workspace packages by name (`@nightshift/db`). No relative imports across packages.
- **Formatting:** Biome. The pre-commit hook formats staged files.
- **Environment:** varlock schemas in `.env.schema`. Generated types, never `process.env` by hand.
- **Prose:** Durable docs follow the ASD-STE100 style of the WTF skills. Short sentences, active voice, one idea per sentence.

## Architecture Decision Records

| Decision | Rationale | Date |
| --- | --- | --- |
| Electrobun, not Tauri | Bun is the main process, so the daemon runs in-process with no sidecar and no IPC seam. | 2026-10-10 |
| libsql, not Postgres | Embeddable now, replicable later, so local mode and server mode share one schema. | 2026-10-10 |
| oRPC, not tRPC | Gives an OpenAPI surface for free. Remote runners and integrations call it later. | 2026-10-10 |
| Every step on a harness | Skills already assume a coding agent's tool belt. Re-implementing it on a raw model is waste. | 2026-10-10 |
| Stateless orchestrator | A resident orchestrator agent is a single point of failure. Short Decision nodes that read durable state are not. | 2026-10-10 |
| Durable facts, derived status, event log | Removes the class of bugs where a late hook overwrites a state. | 2026-10-10 |
| GitHub as TanStack AI tools on `gh` | `gh` already holds the user's login and matches what the skills call. Tools make it callable from Agent and Decision nodes. Superseded on 2026-10-16: GitHub is a CLI tool and a command recipe; the engine knows no tracker. | 2026-10-15 |
| Better Auth always | One identity model. Local mode auto-creates one user. | 2026-10-10 |
| Spaces are Better Auth organizations; one person on one computer gets a local session | A Space is the unit of sharing, with roles checked by the organization plugin on the server. A request from this computer without a session acts as the computer's Person, so nobody signs in to a single-computer Night Shift. See `docs/research/devices.md`, slice 2. | 2026-10-19 |
| Flows as repo files | Versioned, reviewable, diffable. Configuration drift was the main pain in the tool this replaces. | 2026-10-15 |
| The flow is the method | A personal tool needs no method plugin system. A flow with prompts and skills expresses WTF or any other method. | 2026-10-15 |
| React Flow for the editor | Mature graph editor for React. Custom nodes per node type. | 2026-10-15 |
| Step timing, stop and waits stay engine code, not LangGraph's `TimeoutPolicy`, `RunControl` or `retryPolicy` | A LangGraph node timeout drops the node's writes and leaves it running; a drain is not persisted; retries sleep in-process. See `docs/research/langgraph-thinning.md`. | 2026-10-17 |
| The walk reads the checkpoint; the event log is the read model for people, and the crash-recovery source | Writes before `interrupt()` are not committed, and a daemon death mid-node leaves only the log. What the checkpoint holds for sure (outputs, stop time, streak, open Gate) is read there. | 2026-10-17 |
| Project readiness check with guided fixes, never a silent install | Worktrees need git, a top-level repository and a first commit. Night Shift checks them in order and offers a fix per problem after one confirm: the OS installer for git (a command to run where it needs `sudo`), and `git init` plus a first commit with a repo-local name and email. | 2026-10-18 |
| Run history in one global app data directory per daemon, not per project | The dashboard, inbox and run list read across projects, and the per-database lease keeps the dev and night daemons apart. Transcripts can hold unredacted secrets and grow large, so they stay out of repos. Run export bundles cover sharing one run. | 2026-10-18 |

Full ADRs go in `docs/adr/` when a decision needs more than one line of rationale.

## Known Pain Points

- `@tanstack/ai` moves fast (0.39 → 0.68 in a few months). Pin exact versions and upgrade on purpose.
- Electrobun packaging needs a static web build of TanStack Start. Not yet verified.
- Not yet verified: whether the harness adapters accept our own tools, and whether they expose session resume and the usage-limit reset time.
- `drizzle-orm` is a release candidate.

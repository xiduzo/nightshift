# Night Shift Vision

> Generated by `steer-vision`. Refine this document as the product evolves — do not regenerate from scratch.

Last updated: 2026-11-11

## Product Purpose

People hand work to agents, and then they spend their time watching them. They approve a step, paste an error back, start a stronger model, and check the result. Night Shift lets them engineer that loop once, as a flow that they draw or describe. A flow can do any work: research, monitoring, outreach, operations, content, or code. Each step is an agent session, a command, a tool call, a decision, or a Gate. Work climbs a ladder of agents. Choices climb a ladder of deciders: a rule, a decision model, a large model, a person. The engine owns the order, the retries, the limits and the cost.

The person engineers the loop and is its last rung. They are the final fallback when the ladders run out, and the approver before an act that cannot be undone. A person acts only at a Gate, and the aim is a flow that needs them less with each change.

Night Shift runs on the person's own computers, with their own agent logins. It ran its author's work every night since 2026-10-16. Since 2026-11-07 it is for other people who work with agents too. Since 2026-11-11 it is for anyone who builds a loop of work, technical or not, and code is one domain among many.

## Core Principles

1. **The engine decides, the model advises** — Order, retries, loop limits and gates are code. A Decision node picks one of its options. The engine checks a model's pick against them. A Decision by rule is deterministic: an expression over the run's values, with no model. A model never adds a node or changes the graph.
2. **Local first, your credentials** — Every session, worktree and token stays on the person's own computers. A secret never leaves the Device it is on. Night Shift sends anonymous usage by default. A person can set it to off. A step that sends other data off the machine says so in its node.
3. **The flow is the method** — Night Shift has no built-in opinion on how to do the work. A WTF night is one flow. Another method, in any domain, is another flow.
4. **Durable facts, derived status** — The database stores what happened. Night Shift computes status from facts. Every change appends to an event log. No late hook can overwrite a state.
5. **A Gate is a fallback or an approval** — An unattended run never blocks on a person mid-session. A Gate has two jobs. As a fallback, it decides when a ladder runs out: the last tier of a cascade, or a decider that is not sure enough. As an approval, it asks before an act that cannot be undone: send, publish, trade, merge. Every other choice climbs from a rule to a decider first.
6. **The cheapest rung that holds** — Work and choices climb a ladder, and the person is its last rung. A step records what it cost. A person tunes a flow by its cost and its benefit.
7. **The person leaves the loop** — The person engineers the loop once and then leaves it. A Gate that fires is a signal to improve the flow: a better rule, a better check, a stronger decider. A flow is judged by what it cost and by how often it needed a person.

## Strategic Goals

- [x] One Agent node runs on Claude Code and streams its transcript into the UI.
- [x] A flow drawn in the editor runs worker → check → retry and stops at its loop limit.
- [x] The rpgdotexe night runs as a flow for one full Epic, and `night-shift.py` retires.
- [ ] Night Shift builds Night Shift: its own Epics run through its own flow.
- [ ] One person runs Night Shift on several computers: a laptop and a server pair with a Host, and a flow's steps run where they are placed.
- [ ] From the phone alone, a person starts, follows and unblocks an overnight flow. Night Shift tells them when a Gate waits, on the screen they use. See `docs/research/mobile.md`.
- [ ] Another person runs Night Shift for a week on their own agents, with no help from the author.
- [ ] One flow that is not code runs every day for a month.
- [ ] For each flow, a person sees where the work landed on each ladder, what each rung cost, and how often the flow needed them.
- [ ] A project can live without a folder. Its flows run, and a Host runs its schedules without a GitHub remote.
- [ ] A person who never opened a terminal installs Night Shift, sets up an agent and a decider, and finishes a first run.
- [ ] A community flow from someone other than the author lands in `community/`.

## Bounded Contexts

| Context | Responsibility | Key domain objects |
| --- | --- | --- |
| Flow | What a flow is: nodes, edges, outcomes, loop limits, the schema, the validator. | Flow, Node, Edge, Outcome, Agent Profile |
| Run | How a flow runs: graph walk, run policy, item order of a Call with `each`, gates, decisions. | Run, Step Run, Gate, Decision, Run Policy |
| Session | One harness session: transcript, tool calls, needs-input, resume. | Session, Transcript, Step Report, Needs Input |
| Tools | What a flow and its agents reach outside the harness. All of it is foundational, with no integration settings of a vendor: CLI tools such as `gh` and `acli`, MCP connections, HTTP, and webhooks. The engine knows no tracker and no vendor. | CLI Tool, Connection, Profile, Webhook |
| Workspace | Projects, their folders, and local settings. | Workspace, Project, Clone |
| Devices | The computers that run Night Shift, the Hosts they pair with, and what syncs between them. | Device, Host, Link, Replica, Space |
| Notifications | Whom to tell about a Gate or a run, about what, on which screen, and when to stay quiet. The phone as a Person's client of a Host. | Notification settings, Quiet hours, Push target, Phone |

The Run context speaks only in Flow, Node, Step Run, and Gate. The words of a method or a domain (Epic, Trace, a lead) live in prompts, skills, and the list source of a Call node, never in the engine.

## Out of Scope

- Teams beyond invited colleagues in a shared Space. (Since 2026-10-19, in scope: several computers of one person, a Host on a server or the desktop app, and shared runners through Offers. See `docs/research/devices.md`.)
- Method packages, a `method.json` manifest, and OpenSpec as a built-in method. The flow is the method.
- Vendor nodes: a node that needs the integration settings of one vendor, such as a Slack, GitHub or Jira node. A flow reaches a vendor through its CLI, HTTP, webhooks or MCP, and kits build on those.
- A terminal emulator inside the app. A session is a transcript. A takeover is a resume command.
- Running models without a harness CLI, except a decider (a Decision or a Value decided by a model).
- Windows. (A headless Linux Device comes with devices slice 7. Since 2026-10-21, a phone app is in scope: a Person's client of a Host that reads and acts. See `docs/research/mobile.md`.)
- On the phone: editing flows and schedules, store submission, a publisher push relay for other people's Hosts, Apple Watch, end-to-end encrypted push.

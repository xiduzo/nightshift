# Night Shift Vision

> Generated by `steer-vision`. Refine this document as the product evolves — do not regenerate from scratch.

Last updated: 2026-10-15

## Product Purpose

A developer who works with coding agents runs the same pipeline every night: build, check, retry, rescue, open a pull request, review. Today that pipeline is a script. Nobody can see it, and a change to it is a code change. Night Shift turns the pipeline into a flow that you draw. Each step is an agent session with a prompt and/or a skill, a command, a decision, or a gate. The engine owns the order, the retries, and the run policy. You step in only at a gate.

Night Shift is for its author first. It runs on the author's machine with the author's own credentials. It grows to more people only after it runs every night without help.

## Target Users

| Actor | Context | Primary goals |
| --- | --- | --- |
| Developer | The author. Owns a clone of the repo and the coding-agent CLIs. Draws flows, starts runs, and resolves gates. | Draw a flow, hand it an Epic, wake up to a stack of pull requests, take over a session when it needs a person. |

## Core Principles

1. **The engine decides, the model advises** — Order, retries, loop limits, and gates are code. A Decision node returns a label that a schema validates. A model never adds a node or changes the graph.
2. **Local first, your credentials** — Every session, worktree, and token stays on the user's machine. A step that sends data off the machine says so in its node.
3. **The flow is the method** — Night Shift has no built-in opinion on how a spec is written. A WTF night is one flow. Another method is another flow.
4. **Durable facts, derived status** — The database stores what happened. Status is computed from facts. Every change appends to an event log. No late hook can overwrite a state.
5. **People at gates only** — An unattended run never blocks on a person. A step that needs input ends with a report, and the gate waits in an inbox.

## Strategic Goals

- [ ] One Agent node runs on Claude Code and streams its transcript into the UI.
- [ ] A flow drawn in the editor runs worker → check → retry and stops at its loop limit.
- [ ] The rpgdotexe night runs as a flow for one full Epic, and `night-shift.py` retires.
- [ ] Night Shift builds Night Shift: its own Epics run through its own flow.

## Bounded Contexts

| Context | Responsibility | Key domain objects |
| --- | --- | --- |
| Flow | What a flow is: nodes, edges, outcomes, loop limits, the schema, the validator. | Flow, Node, Edge, Outcome, Agent Profile |
| Run | Executing a flow: graph walk, run policy, For Each ordering, gates, decisions. | Run, Step Run, Gate, Decision, Run Policy |
| Session | One harness session: transcript, tool calls, needs-input, resume. | Session, Transcript, Step Report, Needs Input |
| Tools | What an agent can call outside its harness: CLI tools such as `gh` and `acli`, and MCP connections. The engine knows no tracker. | CLI Tool, Connection, Profile |
| Workspace | Projects, repos, and local settings. | Workspace, Project, Repo Binding |

The Run context speaks only in Flow, Node, Step Run, and Gate. A method's own words (Epic, Feature, Trace) live in prompts, skills, and the For Each source, never in the engine.

## Out of Scope

- Other users, teams, and shared runners, until the personal tool runs every night.
- Method packages and a `method.json` manifest. The flow is the method.
- OpenSpec, Jira, and server mode.
- A terminal emulator inside the app. A session is a transcript. A takeover is a resume command.
- Running models without a harness CLI, except a Decision node's decider.
- Windows, Linux, and mobile.

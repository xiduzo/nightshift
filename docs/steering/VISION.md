# Night Shift Vision

> Generated by `steer-vision`. Refine this document as the product evolves — do not regenerate from scratch.

Last updated: 2026-10-10

## Product Purpose

Teams that work with coding agents lose their work in two places. The specs live in one tool. The agent sessions live in terminals that nobody else can see. Night Shift puts one deterministic pipeline between them. A spec-driven method (WTF, OpenSpec, or another) runs as a sequence of agent sessions. The engine owns the order, the retries, and the gates. People step in only at a gate. The specs stay where the team keeps them.

Night Shift runs on the user's machine with the user's own credentials. The daemon is the product. The desktop app makes the daemon usable for every person on the team, not only the one who can run a script.

## Target Users

| Actor | Context | Primary goals |
| --- | --- | --- |
| Developer | Owns a clone of the repo and a coding-agent CLI. Starts runs and resolves technical gates. | Hand a Feature to the pipeline, wake up to a stack of pull requests, take over a session when it needs a person. |
| Product Owner | Writes and approves Epics and Features. Does not read code. | Write a spec in chat, approve a scenario change, see what shipped. |
| QA Engineer | Verifies scenarios and files bugs. | See which claimed scenarios passed, verify a Trace, report a defect against a Trace. |
| Runner Operator | Keeps a headless machine that runs nights for the team. | Register a runner, cap its load, watch its sessions. |
| Method Author | Maintains a method package: its skills, artifact types, and flows. | Ship a method that any Night Shift project can bind. |

## Core Principles

1. **The engine decides, the model advises** — Order, retries, locks, and gates are code. A model returns a decision that a schema validates. A model never reorders work or changes scope on its own.
2. **Local first, your credentials** — Every session, worktree, and token stays on the user's machine. The app holds as little as possible. A server deployment is a later placement of the same daemon, not a different product.
3. **The method is a plugin** — Night Shift has no opinion on how a spec is written. A method package declares its artifacts, its flows, and its skills. Two methods ship so no single one hides the seams.
4. **Durable facts, derived status** — The database stores what happened. Status is computed from facts. Every change appends to an event log. No late hook can overwrite a state.
5. **People at gates only** — An unattended run never blocks on a person. A step that needs input ends with a report, and the gate waits in an inbox that writes back to the artifact.

## Strategic Goals

- [ ] A Developer runs a full WTF Feature unattended from the desktop app and merges the resulting stack the next morning.
- [ ] A Product Owner writes an Epic through chat and never opens a terminal.
- [ ] A second method (OpenSpec) runs on the same engine with no change to the engine.
- [ ] Night Shift builds Night Shift: its own Epics run through its own pipeline.
- [ ] A team runs one daemon on a shared machine with laptops as runners.

## Bounded Contexts

| Context | Responsibility | Key domain objects |
| --- | --- | --- |
| Method | What a spec-driven method is: artifact types, lifecycle states, flows, skills, detection. | Method Package, Artifact Type, Flow, Step, Agent Profile |
| Run | Executing a flow against a project: frontier, scheduling, run policy, gates, orchestrator decisions. | Run, Step Run, Gate, Decision, Lock, Run Policy |
| Session | One harness session on one runner: transcript, tool calls, needs-input, resume. | Runner, Session, Transcript, Tool Call, Needs Input |
| Connector | Reading and writing artifacts and code-host objects on behalf of a project. | Artifact Connector, Code-Host Connector, Artifact, Pull Request, Stack |
| Workspace | Who may do what, where: tenancy, projects, repos, bindings, configuration. | Workspace, Project, Repo Binding, Member, Project Config |

The Method context speaks the method's own language (for WTF: Epic, Feature, Trace, Spine, Scenario Claim). The Run context speaks only in Flow, Step, and Gate. The translation happens in the method package, never in the engine.

## Out of Scope

- Hosting a multi-tenant service with billing. Server mode is self-hosted.
- A terminal emulator inside the app. A session is a transcript. A takeover is a resume command.
- Running models itself without a harness CLI. Every step runs on a harness.
- Windows, until macOS and Linux are solid.
- A visual flow builder, until two real flows exist to generalize from.
- Mobile apps.
